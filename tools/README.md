# tools/

Every file in this directory, with what it does. One tree may carry several
targets (a target is configured when `config/link_order.<slug>.txt` exists);
the tools work on the target `ico_version.py` reports (`VERSION=<slug>`, or
the first configured one, `pal` on `main`), and the config, base file, build
(`build/<slug>/`) and progress (`docs/<slug>/`) paths below follow that slug.
One source tree (`ico2/`, `sce/`) serves every target: where a target
differs, the file holds its lines inline in `#ifdef VERSION_<SLUG>` blocks,
and `compile_c.sh` defines `VERSION_<SLUG>` (and `LN`, a source line number
per target) for the target it compiles. `check_targets.py` holds the tree to
the configured link orders. The files here, `../build.sh`,
`../.github/` and `../docs/index.html` are the same on every branch that
builds a target (`check_shared_layer.sh`), except `dev_native_allow.txt`,
which lists sites in the branch's own sources. `tools/cc/` is fetched and
built by `setup.sh` and is not tracked. `../build.sh` at the repository root runs `setup.sh` and
`extract_elf.sh` when their output is missing, then `build.sh setup` (or
`build.sh verify` once `build.ninja` exists) and ninja, whose last step is the
gate; `build.sh gate-all` gates every configured target.

| tool | what it does |
|---|---|
| `setup.sh` | idempotent host setup: the venv from `requirements.txt`; the period compilers ee-gcc 2.9-991111 and ee-gcc 2.96 (for its SCE 2.10 assembler) from decompme/compilers into `tools/cc/`; a check for `mips-linux-gnu-objcopy`; GNU ld 2.10 with the two patches below and ps2dev's dvp-as with the third, built from public source; the git hooks |
| `requirements.txt` | the venv's Python packages: pyelftools, pycdlib, ninja, clang-format |
| `binutils-2.10-ee.patch` | the R5900 machine and the DVP overlay section types for GNU ld 2.10, backported from ps2dev's `binutils-2.14-PS2.patch`; applied by `setup.sh` |
| `binutils-2.10-dvp-ld.patch` | the Cygnus "sky" ld's DVP rule for GNU ld 2.10: each `.DVP.overlay.*` orphan gets its own output section at address 0 (from the GPL ee-gcc 2.9-991111 combined tree's `ld/emultempl/elf32.em`); applied by `setup.sh` after the first |
| `binutils-dvp-overlay-fill.patch` | for ps2dev's dvp-as: writes the byte each `.DVP.overlay.*` section repeats, which the assembler left to whatever its heap held; `--overlay-fill=N` (default 0) for the constant-address overlays, 0 for the rest; applied by `setup.sh` to the dvp clone before the build |
| `install_hooks.sh` | writes the pre-commit hook (`check_no_rom.sh`, `check_dev_native.py`, `check_targets.py`, `format.sh --check` on the staged C, then `build.sh gate-all` and `build.sh progress-all` when a staged path can affect the build) and the pre-push hook (`check_shared_layer.sh` on each pushed branch, then `build.sh gate-all` on the pushed tip) |
| `extract_elf.sh` / `extract_elf.py` | reads the user's disc image (`baserom/Ico_PAL.iso` on PAL, `baserom/Ico_KOR.iso` on the Korean disc, `baserom/Ico_JUN26.iso` on the Jun-26-2001 demo, a `.bin` and its `.cue` on the other targets) and writes `baserom/<ver>/baseelf.elf` (the file `SYSTEM.CNF`'s `BOOT2` names, or the DISCS row's `boot` for a demo the disc's menu starts), its `objcopy -O binary` view `baseelf.rom`, and the disc's reference files (on PAL `MAIN.MAP`, `SRCFILE.TXT`, `TRFILE.TXT` and `SYSTEM.CNF`); records or checks the SHA-1s in `config/sha1sums.<ver>.txt` (creating it for a target that has none) |
| `ico_version.py` / `ico_version.sh` | the target slug (`VERSION`, or the first configured one) and the configured ones, its base file, build (`build/<slug>/`), `config/sha1sums.<slug>.txt` and `docs/<slug>/` paths, and the table of each target's disc image, its boot file when `SYSTEM.CNF` does not name it, and how messages name it, for the Python and shell tools |
| `build.sh` | `setup` (delete `build/<slug>/`, verify the base ELF and ROM SHA-1s with `verify_elf.py`, write `build.ninja`), `verify` (the SHA-1s alone; writes `build.ninja` again when it names another target), `regen` (`build.ninja`, after adding a source), `clean` (`build/<slug>/`), `distclean` (`build/` and `build.ninja`), `progress` (runs `check_elf.py --progress`), `gate-all` (every configured target's base files required, then `setup` and `ninja` for each), `progress-all` |
| `gen_ninja.py` | writes `build.ninja` (its first line names the slug; every command runs with that `VERSION`; outputs and ninja's state under `build/<slug>/`) from `config/link_order.<slug>.txt`: a compile rule per C source (`compile_c.sh`), an assemble rule per `.s` source with its archive's assembler, the period cpp (from standard input) and dvp-as for the VU1 programs in `ico2/vusrc/` (with `--overlay-fill=N` when the `.dsm` line carries an `overlay-fill=N` token), the data-only members (`gen_data_c.py` for the schema's members: a stand-in, a layout link, the C, its check), the link with GNU ld 2.10 and `config/link.<slug>.ld`, the ROM view, and `check_elf.py --gate --require-elf-sha` as the last step |
| `compile_c.sh` | compiles one C source, given by its path, from the source's own directory (so `__FILE__` and the relative includes are spelled as the original build spelled them), with `-DVERSION_<SLUG>` and `LN` for the target: ee-gcc 2.9-991111 with the flags of the source's origin (the game `-g -G 8 -fno-common`, Sony's SDK archives `-G 0`, libc, libm and libgcc `-G 0 -fno-builtin`), then the assembler of its archive (ee-as 2.9-991111 for the game, libc, libm and libgcc; SCE's 2.10 assembler for the SDK archives); `DUMP_DIR` adds gcc's RTL dumps under the same flags |
| `period_env.sh` / `period_obstack.c` | runs a period toolchain binary with `period_obstack.c` preloaded, which restores the obstack chunk size of the machine that built the game; ee-as's R5900 short-loop padding depends on it |
| `gen_data_c.py` | reads `config/data_members.<slug>.txt` (its table parser also serves `gen_ninja.py`) and writes each data-only member `config/data_schema.<slug>.txt` types as one C translation unit from the user's own base ELF (`build/<slug>/data/<member>.c`, record types from the header its rows name, its version blocks resolved for the target (`--self-test` runs that on fixed cases), pointers named from the layout link `build/<slug>/ico.layout.elf`, its own strings as literals), its zero stand-in for that link, the linker assignments for `D_<VMA>` labels inside it, and the check of the compiled object against its ROM ranges; nothing it writes is committed |
| `gen_stub_s.py` | campaign scaffolding for a target rebuilt from this tree: reads `config/stubs.<slug>.txt` (rows `<section> <name> <vma_lo> <vma_hi> <tu> [local] [align=N] [lines=N] [file=<stem>] [in=<file.c.inc>] [inline] [def]`; its parser also serves `check_dev_native.py`, `check_elf.py`, `gen_ninja.py` and `match_check.py`) and writes each listed function or data run as `build/<slug>/stubs/<stem>.s` from the user's own base ELF (one `.word` per instruction, no relocations), which its TU includes with `INCLUDE_ASM(stem);` at the function's place in the file (the stem is the name, or `file=` when two statics share one; the line lives in the row's `in=<file.c.inc>` when the function is defined in a `.c.inc` the TU includes, which ninja adds to the TU object's inputs), and the macro's header `build/<slug>/stubs/include_asm.h`, which `compile_c.sh` searches last, so a TU that includes it compiles only while the list has rows. A `lit4`, `rdlit` or `sdlit` row names the range of .lit4, .rodata or .sdata a stubbed function's own constants occupy (gcc's `$LC` strings and constants and its jump tables, the assembler's `li.s` and `li.d` pools, the function's own statics), written after the function's text so the TU's later constants keep their places, and with them the code (every address of a constant in an instruction is a relocated field, so a moved constant changes `.text` too). An `rdlit` or `sdlit` row marked `def` (a stubbed inline function's strings and gcc's other constants, which gcc writes where the function is defined) is written to `build/<slug>/stubs/<stem>.lit.s` instead, which the file reads with `INCLUDE_ASM_LIT(stem);` in the definition's place; the code, `.lit4`, `li.d` pool and jump tables stay with `INCLUDE_ASM` at the end of the file. `--literals [NAME]` derives those rows for a text row (every text row without NAME) from two sides that must agree, the TU compiled on this tree (each function's `.lit4`, `.rodata` and `.sdata` relocations, with what each constant is and which function owns it in gcc's reading order, an inline function at its definition) and the row's own words in the target ELF (`--elf`; the `$gp` and `%hi`/`%lo` addresses they form, by `correlate_elf.py`'s register flow), and writes them after the text row (`--dry-run` prints them); a stubbed inline function's strings and gcc constants get `def`; a constant no row can place (shared with a later function still in C, referenced from the TU's data, a static of the function outside those sections) prints HAND, a count or kind the sides do not share prints DISAGREE, and a row with no definition to put back from `--from` (no C, a nested function, a hand carve whose place is lost) or whose body put back stops the TU compiling prints ABSENT with the target side's addresses alone, while the rest of the TU is derived; a def row added to a function carved without one gets its `INCLUDE_ASM_LIT` line where the definition stood. `--carve NAME` derives the literal rows (unless `--no-literals`), replaces the function's definition in its TU (or `in=` file) with the INCLUDE_ASM line (on the file's bytes; an inline function's line goes to the end of the file, where gcc emits it, with `INCLUDE_ASM_LIT` and the declaration a later address use needs in the definition's place, and for one defined in a `.c.inc` to the end of the including TU, the row marked `inline`; an inline function called after its definition is refused unless every caller is one whose code never reaches the object) and records `lines=N`, `--restore NAME [--from REV]` puts the definition back from REV (default `main`), `--carve-all` and `--restore-all` do every text row; `--check <elf>` names any stub whose range differs from the base, `--list` prints the rows. Every source it reads or writes for a row is the one the target compiles. Nothing it writes under `build/` is committed. On `main` the list has no rows |
| `match_check.py` | the state of one function, or of every function of a TU (`--all`), without the link: compiles the TU with `compile_c.sh` into a scratch object (not under `build/`), reads each function from the object's symbols with its `.text` relocations, and compares its words with the target ELF (the branch's base ELF) at the function's range, the relocated fields masked on both sides and no others (`correlate_elf.py`'s masks and residue classes); the range is `--at <vma>`, the function's row of a `--twins` census file, its stub list row, or its symbol in the last link (`build/<slug>/ico.syms.elf`). Prints `equal`, or the first differing instruction with five instructions of context from both sides (`mips-linux-gnu-objdump`, the object's side naming each relocation) and the residue class. On `main` every function compares equal with the PAL base |
| `object_check.py` | two measurements after a link, or after one that fails: each object's `.text` (the map's rows, or with no map the link order's objects placed in `build/<slug>/ico.layout.elf` by a function symbol unique there) against the target ELF at the object's address, the fields its own relocations fill masked as `match_check.py` masks them, `equal` or the first differing word with its function and both words disassembled; and `--order [TU...]`, each TU's functions in object order against their target addresses (a `--twins` row, the stub list row, or the last link's symbol), naming a function placed before ones the target emits earlier, and for a stub the line out of place (an inline function's stub at the end of the file before inline functions still in C that the target emits first). `--self-test` runs both against `build/<slug>/ico.syms.elf`; on `main` every object compares equal and every TU's order rises |
| `verify_elf.py` | checks a file's SHA-1 against `config/sha1sums.<ver>.txt` |
| `check_elf.py` | `--gate`: every allocated section of the built ELF against the base by address, the NOBITS ranges allocated, the ROM SHA-1 and, with `--require-elf-sha` (the build's verify step), the ELF SHA-1; `--progress`: `docs/<ver>/PROGRESS.md`, `docs/<ver>/progress.json` and README.md's progress block (a row of badges per target with a `docs/<slug>/progress.json`) from the same comparison and the link map, with the bytes from the tracked sources and those generated from the user's disc counted apart; `--full-diff`: the whole file side by side |
| `correlate_elf.py` | finds each PAL function (the `STT_FUNC` symbols of `build/pal/ico.syms.elf`, objects from `build/pal/ico.pal.map`) in another ICO boot ELF: branch-aware boundary scan of the stripped target, instruction streams hashed with every relocation field masked (`%hi` registers followed over the control flow), matching in tiers (anchor, gap, window, free, ordinal); writes `twins.txt`, `pal_only.txt`, `target_only.txt`, `tu_spans.txt` and `report.txt` under `build/pal/correlate/<name>/`; `--self-test` checks the masking against the build's own relocations and matches PAL against itself. Its register flow (`hi_values`) also gives `gen_stub_s.py --literals` the addresses a stub's words form. The census a target branch is seeded from; nothing it writes is committed |
| `check_shared_layer.sh` | on a branch other than `main`, fetches `origin/main` and refuses any difference in `tools/` (but for `dev_native_allow.txt`, left out by a pathspec exclude: its sites are the branch's own), `build.sh`, `.github/` or `docs/index.html`, naming the files; passes on `main` |
| `check_targets.py` | the source tree against the configured targets: every source is in a configured target's link order, every link-order row is a file, no `targets/` directory, a `VERSION_<SLUG>` name only in C sources and headers and only for a configured slug, and only in a version condition of the accepted forms (`#ifdef`/`#ifndef`, `#if defined(...) || defined(...)`, `#if !defined(...) && !defined(...)`, `#elif defined(...)`), each block's arms in order; `--self-test` runs the forms on fixed cases; reads the files git tracks or would track; run by `gen_ninja.py` and the pre-commit hook |
| `check_no_rom.sh` | IP guard: refuses disc images (by extension and by the names `Ico_PAL.*`, `Ico_JPN.*`, `Ico_KOR.*`, `Ico_USA.*`, `Ico_AUG6.*`, `Ico_JUN26.*`), PS2 executables, the disc's reference files (`MAIN.MAP`, `SRCFILE.TXT`, ...), extracted assets, large binaries, raw byte-array initializers in tracked C, and a stub `gen_stub_s.py` writes copied into a tracked source; a stub list (`config/stubs.<slug>.txt`, text rows with no bytes) is exempt from the size cap like `config/symbol_addrs.*.txt`, and the byte-array and `.word`-run rules read it too |
| `check_dev_native.py` / `dev_native_allow.txt` | refuses constructs a developer did not write (K&R definitions, empty `do { } while (0)`, empty asm, symbol aliases, register pins and asm blocks in functions the listing shows were compiled C, file-scope asm that defines such a function, any `INCLUDE_ASM` or `INCLUDE_ASM_LIT` the stub list does not carry, and one with no `#include "include_asm.h"` above it in its file, which compiles with only a warning as a K&R declaration; `--self-test` runs that rule on the file-scope shapes a carve leaves and the ones it refuses) and checks that `compile_c.sh` selects the assembler by archive only; the allowlist holds the ROM-proven exceptions with their reasons |
| `format.sh` / `format_layout.py` | clang-format with the tracked `.clang-format`, then the top-level blank-line layout, a version block's arms (`#if`, `#elif`, `#else`, `#endif`) kept tight; `--check` for the pre-commit hook, `format_layout.py --self-test` for its fixed cases. Under `-g` a line break can move bytes, so the byte gate runs after it |
