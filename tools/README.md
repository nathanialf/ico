# tools/

Every file in this directory, with what it does. The tools work on the
branch's target as `ico_version.py` reports it (`main` is PAL retail, slug
`pal`), and the config and base file paths below follow that slug. The files
here, `../build.sh`, `../.github/` and `../docs/index.html` are the same on
every target branch (`check_shared_layer.sh`), except `dev_native_allow.txt`,
which lists sites in the branch's own sources. `tools/cc/` is fetched and
built by `setup.sh` and is not tracked. `../build.sh` at the repository root runs `setup.sh` and
`extract_elf.sh` when their output is missing, then `build.sh setup` (or
`build.sh verify` once `build.ninja` exists) and ninja, whose last step is the
gate.

| tool | what it does |
|---|---|
| `setup.sh` | idempotent host setup: the venv from `requirements.txt`; the period compilers ee-gcc 2.9-991111 and ee-gcc 2.96 (for its SCE 2.10 assembler) from decompme/compilers into `tools/cc/`; a check for `mips-linux-gnu-objcopy`; GNU ld 2.10 with the two patches below and ps2dev's dvp-as with the third, built from public source; the git hooks |
| `requirements.txt` | the venv's Python packages: pyelftools, pycdlib, ninja, clang-format |
| `binutils-2.10-ee.patch` | the R5900 machine and the DVP overlay section types for GNU ld 2.10, backported from ps2dev's `binutils-2.14-PS2.patch`; applied by `setup.sh` |
| `binutils-2.10-dvp-ld.patch` | the Cygnus "sky" ld's DVP rule for GNU ld 2.10: each `.DVP.overlay.*` orphan gets its own output section at address 0 (from the GPL ee-gcc 2.9-991111 combined tree's `ld/emultempl/elf32.em`); applied by `setup.sh` after the first |
| `binutils-dvp-overlay-fill.patch` | for ps2dev's dvp-as: writes the byte each `.DVP.overlay.*` section repeats, which the assembler left to whatever its heap held; `--overlay-fill=N` (default 0) for the constant-address overlays, 0 for the rest; applied by `setup.sh` to the dvp clone before the build |
| `install_hooks.sh` | writes the pre-commit hook (`check_no_rom.sh`, `check_dev_native.py`, `format.sh --check` on the staged C, then `build.sh setup`, `ninja` and `check_elf.py --progress` when a staged path can affect the build) and the pre-push hook (`check_shared_layer.sh` on each pushed branch, then `build.sh setup` and `ninja` on the pushed tip) |
| `extract_elf.sh` / `extract_elf.py` | reads the user's disc image (`baserom/Ico_PAL.iso` on PAL, a `.bin` and its `.cue` on the other targets) and writes `baserom/<ver>/baseelf.elf`, its `objcopy -O binary` view `baseelf.rom`, and the disc's reference files (on PAL `MAIN.MAP`, `SRCFILE.TXT`, `TRFILE.TXT` and `SYSTEM.CNF`); records or checks the SHA-1s in `config/sha1sums.txt` |
| `ico_version.py` / `ico_version.sh` | the branch's target slug (the first `config/link_order.<slug>.txt` that exists, or `VERSION`), its base file paths, and the table of each target's disc image and how messages name it, for the Python and shell tools |
| `build.sh` | `setup` (delete `build/`, verify the base ELF and ROM SHA-1s with `verify_elf.py`, write `build.ninja`), `verify` (the SHA-1s alone), `regen`, `clean`, `distclean`, `progress` (runs `check_elf.py --progress`) |
| `gen_ninja.py` | writes `build.ninja` from `config/link_order.<slug>.txt`: a compile rule per C source (`compile_c.sh`), an assemble rule per `.s` source with its archive's assembler, the period cpp (from standard input) and dvp-as for the VU1 programs in `ico2/vusrc/` (with `--overlay-fill=N` when the `.dsm` line carries an `overlay-fill=N` token), the data-only members (`gen_data_c.py` for the schema's members: a stand-in, a layout link, the C, its check), the link with GNU ld 2.10 and `config/link.<slug>.ld`, the ROM view, and `check_elf.py --gate --require-elf-sha` as the last step |
| `compile_c.sh` | compiles one C source: ee-gcc 2.9-991111 with the flags of the source's origin (the game `-g -G 8 -fno-common`, Sony's SDK archives `-G 0`, libc, libm and libgcc `-G 0 -fno-builtin`), then the assembler of its archive (ee-as 2.9-991111 for the game, libc, libm and libgcc; SCE's 2.10 assembler for the SDK archives); `DUMP_DIR` adds gcc's RTL dumps under the same flags |
| `period_env.sh` / `period_obstack.c` | runs a period toolchain binary with `period_obstack.c` preloaded, which restores the obstack chunk size of the machine that built the game; ee-as's R5900 short-loop padding depends on it |
| `gen_data_c.py` | reads `config/data_members.<slug>.txt` (its table parser also serves `gen_ninja.py`) and writes each data-only member `config/data_schema.<slug>.txt` types as one C translation unit from the user's own base ELF (`build/data/<member>.c`, record types from the header its rows name, pointers named from the layout link `build/ico.layout.elf`, its own strings as literals), its zero stand-in for that link, the linker assignments for `D_<VMA>` labels inside it, and the check of the compiled object against its ROM ranges; nothing it writes is committed |
| `gen_stub_s.py` | campaign scaffolding for a target rebuilt from this tree: reads `config/stubs.<slug>.txt` (rows `<section> <name> <vma_lo> <vma_hi> <tu> [local] [align=N] [lines=N] [file=<stem>]`; its parser also serves `check_dev_native.py`, `check_elf.py`, `gen_ninja.py` and `match_check.py`) and writes each listed function or data run as `build/stubs/<stem>.s` from the user's own base ELF (one `.word` per instruction, no relocations), which its TU includes with `INCLUDE_ASM(stem);` at the function's place in the file (the stem is the name, or `file=` when two statics share one), and the macro's header `build/stubs/include_asm.h`, which `compile_c.sh` searches last, so a TU that includes it compiles only while the list has rows. A `lit4`, `rdlit` or `sdlit` row names the range of .lit4, .rodata or .sdata a stubbed function's own constants occupy (gcc's `$LC` strings and constants, the assembler's `li.s` and `li.d` pool), written after the function's text so the TU's later constants keep their places. `--carve NAME` replaces the function's definition in its TU with the INCLUDE_ASM line (on the file's bytes; an inline function's line goes to the end of the file, where gcc emits it) and records `lines=N`, `--restore NAME [--from REV]` puts the definition back from REV (default `main`), `--carve-all` and `--restore-all` do every text row; `--check <elf>` names any stub whose range differs from the base, `--list` prints the rows. Nothing it writes under `build/` is committed. On `main` the list has no rows |
| `match_check.py` | the state of one function, or of every function of a TU (`--all`), without the link: compiles the TU with `compile_c.sh` into a scratch object (not under `build/`), reads each function from the object's symbols with its `.text` relocations, and compares its words with the target ELF (the branch's base ELF) at the function's range, the relocated fields masked on both sides and no others (`correlate_elf.py`'s masks and residue classes); the range is `--at <vma>`, the function's row of a `--twins` census file, its stub list row, or its symbol in the last link (`build/ico.syms.elf`). Prints `equal`, or the first differing instruction with five instructions of context from both sides (`mips-linux-gnu-objdump`, the object's side naming each relocation) and the residue class. On `main` every function compares equal with the PAL base |
| `verify_elf.py` | checks a file's SHA-1 against `config/sha1sums.txt` |
| `check_elf.py` | `--gate`: every allocated section of the built ELF against the base by address, the NOBITS ranges allocated, the ROM SHA-1 and, with `--require-elf-sha` (the build's verify step), the ELF SHA-1; `--progress`: README.md's badges, `docs/PROGRESS.md` and `docs/progress.json` from the same comparison and the link map, with the bytes from the tracked sources and those generated from the user's disc counted apart; `--full-diff`: the whole file side by side |
| `correlate_elf.py` | finds each PAL function (the `STT_FUNC` symbols of `build/ico.syms.elf`, objects from `build/ico.pal.map`) in another ICO boot ELF: branch-aware boundary scan of the stripped target, instruction streams hashed with every relocation field masked (`%hi` registers followed over the control flow), matching in tiers (anchor, gap, window, free, ordinal); writes `twins.txt`, `pal_only.txt`, `target_only.txt`, `tu_spans.txt` and `report.txt` under `build/correlate/<name>/`; `--self-test` checks the masking against the build's own relocations and matches PAL against itself. The census a target branch is seeded from; nothing it writes is committed |
| `check_shared_layer.sh` | on a branch other than `main`, fetches `origin/main` and refuses any difference in `tools/` (but for `dev_native_allow.txt`, left out by a pathspec exclude: its sites are the branch's own), `build.sh`, `.github/` or `docs/index.html`, naming the files; passes on `main` |
| `check_no_rom.sh` | IP guard: refuses disc images (by extension and by the names `Ico_PAL.*`, `Ico_JPN.*`, `Ico_USA.*`, `Ico_AUG6.*`), PS2 executables, the disc's reference files (`MAIN.MAP`, `SRCFILE.TXT`, ...), extracted assets, large binaries, raw byte-array initializers in tracked C, and a stub `gen_stub_s.py` writes copied into a tracked source |
| `check_dev_native.py` / `dev_native_allow.txt` | refuses constructs a developer did not write (K&R definitions, empty `do { } while (0)`, empty asm, symbol aliases, register pins and asm blocks in functions the listing shows were compiled C, file-scope asm that defines such a function, and any `INCLUDE_ASM` the stub list does not carry) and checks that `compile_c.sh` selects the assembler by archive only; the allowlist holds the ROM-proven exceptions with their reasons |
| `format.sh` / `format_layout.py` | clang-format with the tracked `.clang-format`, then the top-level blank-line layout; `--check` for the pre-commit hook. Under `-g` a line break can move bytes, so the byte gate runs after it |
