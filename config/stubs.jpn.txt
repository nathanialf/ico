# config/stubs.jpn.txt -- the functions and data runs still built from the base ELF.
#
# Campaign scaffolding. A row names a range of the base ELF that no tracked
# source produces yet; tools/gen_stub_s.py writes it as build/stubs/<name>.s
# from the user's own baserom/jpn/baseelf.elf at build time (nothing of the
# ROM is tracked, docs/LEGAL.md), and the TU the row names includes it with
# `INCLUDE_ASM(name);` (include/include_asm.h) at the function's place in the
# file. tools/check_dev_native.py refuses an INCLUDE_ASM whose name has no row
# here. With no rows the mechanism is idle.
#
# Columns: <section> <name> <vma_lo> <vma_hi> <tu> [local] [align=N]
#   section   text, rodata, data or sdata
#   name      the symbol the stub defines
#   vma_lo/hi the range [lo, hi) in the base ELF, hex (a text row ends at the
#             function's last instruction, not at the fill after it)
#   tu        the C source under ico2/ or sce/ that includes the stub
#   local     the name is a static in the C (no .globl)
#   align=N   the stub's alignment in bytes (default: the largest power of two
#             dividing vma_lo, at most 8)
#   lines=N   the source lines the INCLUDE_ASM line replaced (gen_stub_s.py --carve)
#   file=stem the stub's file and INCLUDE_ASM name when it is not the name
#
# Seeded from the function census against the PAL build, tools/correlate_elf.py
# (the JPN disc ships no map: a name is the PAL listing's name of the twin the
# census found). Two kinds of row:
#   - a PAL function whose JPN twin's body differs: the PAL name, the twin's
#     JPN range, and the PAL source that defines it. The trailing comment gives
#     the census tier (anchor, gap, window, free or ordinal), the first
#     differing instruction, the residue class and whether the extents agree.
#     Every such pair is ordinal: paired by position inside a gap, so its name
#     is provisional until the function matches from the PAL source.
#   - a JPN function no PAL function claims (`jpn-only`): a derived name
#     func_<VMA> and the source whose span holds it by link order; the
#     comment says what PAL size and order suggest, which is not a name.
#
# Left out of the census's JPN-only list: 0x1000C0 (80 bytes) is PAL's _root,
# its fill and RFU000_FullReset, byte-identical, merged by the boundary scan
# (crt0.s and klib.s, a function ending in a syscall); 0x2642F8, 0x2643A4 and
# 0x2643AC are PAL's sceSifWriteBackDCache and CB_DelayTh, byte-identical,
# split elsewhere by the scan (a dead jr after a return). The census also
# pairs actSt00aDoor2 (free tier, bodies equal) with 0x2204A0, which by order
# and size is st02a.c's actSt02aDoor; that pair is equal and has no row.
#
# A name that two TUs define (gene_enemy) takes file=<stem> on its second
# row; a nested function's row (name.N) takes file=<stem> as well, since a
# stem is a C identifier.
#
# Rows added after the census, each with its reason on the line:
#   - the census's PAL-only and jpn-only lists hold the same functions in
#     layout_action.c, st00a.c, BgAnimation.c and windmill.c (same size and
#     order): those rows carry the PAL name;
#   - a nested function (name.N) whose enclosing function is a stub, and
#     a function equal in C whose nested function is a stub;
#   - a static inline function whose out-of-line copy only a stubbed
#     caller needed, so gcc no longer emits it;
#   - "a stub for emission order": gcc 2.9 emits an inline function after
#     everything the file defines in place and after every INCLUDE_ASM, so
#     every inline function the JPN emits before a stubbed one is a stub
#     too; and a function equal in C that inlines one of those;
#   - functions the census counted equal with immediates masked, whose
#     immediates differ;
#   - data rows for function-scope statics in .data that a carved
#     function defined.
