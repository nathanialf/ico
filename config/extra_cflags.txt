# Per-file CFLAGS overrides for src/cod/<FILE_OFF>.c.
#
# Format: <FILE_OFF_HEX>  <extra-flags...>
# Lookup: tools/extra_cflags.sh extracts FILE_OFF from the .c basename
# (uppercased) and prints any matching extra flags. Empty output ⇒ no
# override. Used by the Makefile src/.o rule and tools/quick_diff.sh so
# both pipelines stay in sync.
#
# When to add an entry: a single function (or small cluster) needs a
# compiler flag that would break the global SHA-1 if applied to all of
# src/. Verify with `make clean && make` after adding an entry, and remove
# the entry the moment the underlying need disappears.
#
# Lines starting with # are comments; blank lines ignored.

# The 2.96-era `0F4C00 -fno-schedule-insns2` was retired when the project
# moved to ee-gcc 2.9-991111 (whose default scheduler already produces the
# matching shape).
#
# `-fno-schedule-insns` (first-pass scheduler off) per-file: ee-gcc's first-pass
# scheduler picks an `addiu a2; sd ra` prologue order whereas the original emits
# `sd ra` between `lui a2` and `addiu a2`. Disabling only the first-pass
# scheduler for these TUs restores the matching prologue.
#
# Tested promoting to global CFLAGS — broke 2.2M bytes of matched .text, so the
# first-pass scheduler is load-bearing for the rest of the codebase; these stay
# per-file. tools/global_flag_sweep.py `prune` verified this is the load-bearing
# remainder — redundant entries (BASIC, 090408, 0B5958, 145120, 145178) were
# removed when they began matching without the flag.

# Coalesced TUs with matched function bodies sandwiched between
# INCLUDE_ASM blocks need 4-byte function alignment to land their
# matched bodies at the original VMA offset. ee-gcc 2.9 defaults to
# .p2align 3 (8-byte) which adds +4 byte pad when the matched body's
# VMA mod 8 == 4, cascading SHA-1 mismatch.
SWITCH -malign-functions=2
S_INIT -malign-functions=2
# func_001FB5E0 also has a loop top, so its .p2align 3 needs demoting too.
DISPLAYLIST -malign-functions=2 -malign-loops=2
0D4E30 -fno-schedule-insns

# act-game: func_0014A100 writes a vec3 to a float* dst while re-reading the
# obj->0x15C->0xC mesh-base pointer chain for each component. The original
# reloads that chain across the float stores (no TBAA); the strict-aliasing
# default lets gcc CSE the chain to a single base. -fno-strict-aliasing
# restores the per-store reload. tools/tu_check.py confirms all matched
# act-game funcs stay byte-identical with this flag.

# act-env: func_00200970 copies the D_0061AD10 vec4 into a local then copies a
# vec3 within the obj; the original orders the local-buf stores ahead of the
# obj vec-loads (no TBAA reorder). -fno-strict-aliasing restores that order.
# tu_check confirms the matched sibling stays byte-identical.
ACT-ENV -fno-strict-aliasing
